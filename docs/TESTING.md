# Проверка Mikan Remote

## Автоматическая проверка

Workflow Verify Windows выполняет TypeScript/Vite build, генерацию иконок, имеющиеся Rust-тесты и релизную сборку EXE. Установщик NSIS не собирается. Готовый EXE сохраняется как артефакт на 7 дней.

CI не получает API-ключ, не подключается к Mikan и не изменяет её данные. Зелёный workflow подтверждает прохождение этих команд, а не полную проверку интерфейса, защиты секретов или совместимости панели. Выбранные зависимости без lock-файлов могут меняться между запусками.

Результат проверяйте во вкладке Actions → Verify Windows. Красный шаг означает, что следующие проверки не завершились. Сохраните лог первого упавшего шага; не объявляйте тестирование успешным по факту появления коммита.

## Локальная проверка

Обновите исходники. Закройте запущенный EXE. Команды выполняйте из корня проекта по очереди:

```powershell
npm.cmd install
npm.cmd run build
npm.cmd run tauri -- icon app-icon.svg
cargo test --manifest-path .\src-tauri\Cargo.toml
npm.cmd run tauri dev
```

Не публикуйте ключи, секретный адрес панели, ссылки подписок и клиентские данные.

## Проверка интерфейса без изменений панели

- Название окна и бокового меню: Mikan Remote, новая иконка M.
- Нет переключателя демо и вымышленных показателей.
- Без подключения запросы показывают ошибку, не фальшивый успех.
- Подключение с ключом чтения; загрузка главной, пользователей, нод, подключений и пресетов.
- Выбор разных нод показывает соответствующие подключения; отсутствующее поле не подменяется нулём.
- Переключение разделов во время загрузки не вызывает падение.
- Отмена подтверждения не отправляет изменяющий запрос.
- Проверка узкого окна и клавиатурной навигации.

## Интеграционные операции

Используйте отдельную тестовую панель/ноду и тестового пользователя, не действующих клиентов. Выполняйте изменяющие действия только после проверки цели в подтверждении приложения.

- Создать тестового пользователя по тарифу и проверить его в самой Mikan.
- Изменить заметку и лимиты; проверить соответствие в панели.
- Убедиться, что ноль трафика и снятие лимита — разные действия.
- На тестовой ноде создать подключение из пресета; проверить ноду, порт и результат в Mikan.
- Включить/отключить только тестовое подключение, проверить состояние в панели.
- Изменить его порт и проверить состояние. Не применять к рабочему подключению.
- Попробовать операции записи ключом чтения: ошибка должна быть явной.
- При потере ответа сначала загрузить фактическое состояние; не повторять создание вслепую.

Принятие API-запроса не доказывает работоспособность VPN. Проверка настоящего клиентского соединения выполняется отдельно. Восстановите тестовые параметры и удалите тестовые сущности средствами панели после проверки, отдельно подтверждая удаление.

## Отчёт

Запишите SHA тестируемого коммита, версии приложения/Mikan/Windows, выполненный сценарий, ожидаемый и фактический результат. Статусы: пройдено, ошибка, не проверено. Не заменяйте «не проверено» на «пройдено».
