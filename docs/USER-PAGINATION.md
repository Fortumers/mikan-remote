# Серверные параметры пользователей — Rust-этап

Статус: код не проверен сборкой/тестами на Windows. Интерфейс пока не использует новые параметры: страницы, сортировка и поиск таблицы остаются локальными.

Команда get_collection принимает необязательные limit, offset, query, userState для kind=users. Параметры проверяются, поиск URL-кодируется. Вызов только с kind сохраняет прежнее поведение.

Пример будущего вызова из React:
invoke('get_collection', { kind: 'users', limit: 25, offset: 50, query: 'тест', userState: 'active' })

Схема оригинальной Mikan: limit 1..500 (100 по умолчанию), offset >=0, q до 100 символов, state all/active/expiring/limited/expired/disabled/attention. Ответ содержит items и total. Установленную версию ещё нужно проверить.

Для payments/nodes дополнительные параметры отклоняются: их пагинация не предполагается по аналогии. Сортировка на сервере не реализована этим изменением.

Тесты проверки параметров и URL-кодирования добавлены, но не запускались. Из корня: npm.cmd run tauri -- icon app-icon.svg; затем cd src-tauri и cargo test. Для запуска: из корня npm.cmd run tauri dev.

Следующий этап — связать таблицу пользователей с серверными страницами, поиском и total; не выдавать локальное разбиение за серверную пагинацию.
